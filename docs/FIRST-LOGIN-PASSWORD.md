# Admin-created student first login (Spark)

For new accounts created through **Add Student**, the username is the Student ID and the initial password is the birthday in **MMDDYYYY** format. For example, January 2, 2005 becomes `01022005`. The administrator must provide a valid birthday; the form displays the derived temporary password read-only. Invalid/future birthdays are rejected before creating an Auth account. The password is sent only to Firebase Authentication, not stored in Firestore.

The new profile has `mustChangePassword: true`. The existing student dashboard opens its required password-change modal, makes the rest of the app shell inert, and keeps keyboard focus within the modal. Students can choose an 8–128-character password, confirm it, or sign out. Birthday-password and Student-ID reuse are rejected. The password is updated in Firebase Auth first, then the existing profile flag is cleared. If updating the profile fails afterward, the password may already have changed: sign in with the new password and retry. Existing accounts and self-registration are not modified. Editing an existing profile does not reset its password or re-enable the prompt.

This is the **app-level Spark workflow**, not strict server enforcement. Firestore rules cannot prove the user changed their Firebase Auth password before clearing a client-writable flag. A modified client can bypass the prompt. Birthday passwords are predictable and are not proof of identity; share account access privately, verify the student's identity and arrange prompt first login. Do not treat a known Student ID plus birthday as sufficient identity verification.

No new Cloud Functions, billing changes, or new Firestore fields/rules are needed. The repository's current rules already permit the existing `mustChangePassword` workflow; make sure those rules are already deployed. Publish the updated website and rebuild the APK before using this workflow on students' devices. Previously built APKs do not contain these new changes.

Test with a new admin-created account: verify ID + MMDDYYYY login, mandatory prompt, birthday/ID/short/mismatched password rejection, successful password change, sign-out/re-login with the new password and no repeated prompt. Check that the old birthday password fails afterward. Also test a legacy account and edit an existing student: their passwords must be unchanged. No live student accounts are created by automated tests.
